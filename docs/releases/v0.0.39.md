# Naut v0.0.39

## Highlights

- Presentation Contract 4 extends declarative layouts with layered Gallery scenes, responsive navigation, control skins and coordinated Global Presets. Components remain independently selectable.
- Home and Profile support multiple Banner slots, with bounded playback and shared decoding for identical video sources. Cover and Frame customization previews retain their actual artwork proportions.
- The built-in collection and four official optional packs have updated visual compositions. Official pack source versions are 4.0.0; the documented example demonstrates Contract 4 authoring.
- Official pack update checks validate signed registry metadata. The 4.0.0 archives and signed registry are published separately on Pages; see [pack installation and signed updates](../pack-collection.md). Pack updates remain separate from application replacement and Vault media.
- Import Review supports bulk retry, duplicate reuse, Profile collision decisions and removal across all pages without bypassing verification or deleting original files.
- Import intake preserves source-object identity, records explicit Profile Add Media intent atomically, distinguishes unreadable sources from unsupported formats, and validates model dependency paths and discovery limits.
- Vault Health distinguishes missing, misplaced and mismatched canonical originals. Explicit verified repair preserves identity, source bytes and damaged evidence; recorded unhealthy originals cannot be reused by duplicate import. Deep checks include SQLite integrity and foreign keys.
- See [measured performance](../performance.md) for the matched video-decoder comparison and its limitations.

## Download and update

Download the [Windows x64 ZIP](https://github.com/secondshift-dv/naut/releases/download/v0.0.39/naut-v0.0.39-win-x64.zip) from GitHub Releases. New users extract the complete archive and launch naut.exe. Existing users can check for the signed update from Settings. Back up the complete Vault before opening it with this version.

## Notes

Catalog schema advances to 4 through an atomic migration at Vault startup. Older builds reject the newer catalog; downgrade requires a pre-upgrade Vault backup. Contract 4 retains earlier presentation-pack compatibility; a Contract 4 pack requires a compatible renderer. Application updates remain separate from Vault storage.
