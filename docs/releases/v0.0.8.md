# Naut v0.0.8

Naut v0.0.8 refines durable Import transfer bookkeeping without changing how personal media is preserved or processed.

## Highlights

- **No duplicate checkpoint flush at end of transfer.** A file that finishes exactly on an already-durable checkpoint no longer incurs an additional disk flush and SQLite checkpoint update at the same offset. For example, a 128 MiB source using the normal 64 MiB interval needs two durable writes, not three. A remaining partial block and resume-after-interruption still persist the required final offset.
- **Less repeated checkpoint parsing.** Transfer reuses the verified Import item identity that was established when the job started, rather than deserializing it again at every checkpoint.
- **Preserved Import experience.** Original sources stay untouched; SHA-256 validation, duplicate reuse, People analysis, metadata, Thumbnail/Hover/Figure preparation, safe Cancel and restart recovery retain their existing behavior. The buffer remains 1 MiB and the default durable checkpoint spacing remains 64 MiB.

## Notes

- Official releases and signed updates are distributed exclusively through `secondshift-dv/naut`; development builds from `naut-dv` are not public releases.
- The optimization reduces redundant checkpoint operations on sources whose length falls exactly on the durable boundary; it does not promise a fixed percentage improvement in total Import time. File sizes, storage speed, metadata decoding, media derivatives and optional People analysis determine total duration.
- Automated development verification covers synthetic duplicate detection, source/staging hashes, cancel and recovery, WPF dispatcher heartbeat under controlled interaction modes, image/video metadata and derivatives, Face Review persistence, and supported model preparation on isolated fixtures. Hosted-runner dispatcher timing is not a visual UI acceptance test or a representative HDD benchmark. Real-world YuNet/SFace accuracy and end-to-end performance on personal collections are not claimed.
- Existing Vault schema, external-file ownership, updater integrity checks, saved presentation choices and installed packs remain unchanged. No additional operating-system prerequisite is introduced.
